# 02 — Canonical Schema Extensions (Drizzle ORM Contract)

All column additions below extend existing tables in `server/db/schema.ts`, using snake_case SQL names mapped to camelCase TypeScript fields. They are **additive only**: nothing is dropped, and every new column has a safe default so existing rows stay valid.

---

## 1. `workspace_settings` Extensions

```typescript
// Additive columns for server/db/schema.ts -> workspace_settings
businessType: text('business_type').notNull().default('SARI_SARI'), // 'SARI_SARI' | 'HARDWARE' | 'AGRIVET' | 'BAKERY' | 'SCHOOL_SUPPLY'
requireCustomerName: boolean('require_customer_name').notNull().default(false),
requireSaleStatus: boolean('require_sale_status').notNull().default(false),
enableUnitConversions: boolean('enable_unit_conversions').notNull().default(true),
columnMappingJson: jsonb('column_mapping_json').$type<Record<string, string>>().notNull().default({}),
```

## 2. `inventory_items` Extensions (Live Offline Retail Catalog)

```typescript
// Additive columns for server/db/schema.ts -> inventory_items
unitPrice: numeric('unit_price', { precision: 14, scale: 2 }).notNull().default('0.00'),
aliases: jsonb('aliases').$type<string[]>().notNull().default([]),
baseUnit: text('base_unit').notNull().default('pc'), // 'pc' | 'kg' | 'g' | 'pack' | 'meter' | 'liter' | 'sack' | 'box' | 'sheet' | 'tasa' | 'tray' | 'ream'
parentProductId: uuid('parent_product_id'), // Parent bulk item; relation is validated by the workspace route
conversionFactor: numeric('conversion_factor', { precision: 10, scale: 3 }).notNull().default('1.000'),
isAutoGeneratedSku: boolean('is_auto_generated_sku').notNull().default(false),
```

Stock and reorder quantities use `numeric(12,3)` in PostgreSQL. SQLite retains its existing tables and uses its numeric affinity for fractional stock. `conversionFactor` means child units yielded from one parent unit.

### Break-Pack Guardrail Rule

When converting 1 bulk unit (e.g., a `50kg Feed Sack`) into *tingi* child units (`50 x 1kg Repack`), run both updates inside a single atomic transaction with a strict non-negative stock check:

```sql
-- Fails safely if parent stock < 1
UPDATE inventory_items
SET quantity = quantity - 1, last_updated = :today
WHERE id = :parent_product_id AND quantity >= 1;

-- Only increment child stock if the parent row was updated (ROW_COUNT = 1)
UPDATE inventory_items
SET quantity = quantity + :conversion_factor, last_updated = :today
WHERE id = :child_product_id;
```

The workspace implementation wraps both statements in one SQLite transaction and verifies the child is linked to the selected parent. The PostgreSQL `products`/`inventory_batches` subsystem remains separate pending the catalog mapping milestone.

## 3. Sales & Historical Archive Extensions

```typescript
// Additive columns for sales / transaction line items
unitSold: text('unit_sold').notNull().default('pc'),
unitPrice: numeric('unit_price', { precision: 12, scale: 2 }).notNull(),
unitCostSnapshot: numeric('unit_cost_snapshot', { precision: 12, scale: 2 }).notNull().default('0.00'),
discountAmount: numeric('discount_amount', { precision: 12, scale: 2 }).notNull().default('0.00'),
amountPaid: numeric('amount_paid', { precision: 12, scale: 2 }).notNull().default('0.00'),
recordSource: text('record_source').notNull().default('POS_LIVE'), // 'POS_LIVE' | 'CSV_IMPORT' | 'NOTEBOOK_ARCHIVE'
deductStock: boolean('deduct_stock').notNull().default(true),
extraMetadata: jsonb('extra_metadata').$type<Record<string, unknown>>().notNull().default({}),
```

`unitPrice` already existed in the sales table. New sales fields use defaults so existing rows remain valid; sales quantity becomes `numeric(12,3)` for fractional units.
